# CraftPlanner 操作ガイド

ゲームのアイテム・素材・レシピを登録し、目標アイテムの制作に必要な素材と不足数を
自由なキャンバス上で整理・計算する Windows アプリです。

---

## 1. 起動と画面構成

* `dotnet run --project src/CraftPlanner.App` または Visual Studio で `CraftPlanner.App` を実行します。
* 画面は左が **アイテム一覧**、右が **制作計画のタブ**、下が **ステータスバー**（保存状態）です。
* 初回起動時は「新しいゲーム」というゲームデータが 1 つ作られます。名前は「ゲームデータ > ゲームデータの管理…」で変えられます。

### データの保存場所

```
%LOCALAPPDATA%\CraftPlanner\
  games\      ゲームデータ（アイテム・レシピ）。1 ゲーム 1 ファイル
  plans\      制作計画。1 計画 1 ファイル
  backups\    保存のたびに作られる直前の世代（既定 10 世代）
  logs\       動作ログ（30 日で自動削除）
  settings.json  開いていたタブ、ウィンドウサイズなど
```

「ファイル > データフォルダーを開く」で開けます。
環境変数 `CRAFTPLANNER_DATA_DIR` を設定すると、その場所をデータフォルダーとして使います（検証用）。

このアプリは **上記フォルダー以外のファイルを勝手に読み書きしません**。例外は、ユーザーがファイルダイアログで明示的に選んだ画像・JSON・CSV の読み込みと、書き出し先への保存だけです。外部通信は行いません。

---

## 2. アイテムとレシピの登録

### アイテム

1. 左の一覧で **「新規」** を押す（または Ctrl+F で検索して見つからなければ「新規」）。
2. **名前** だけ入力すれば登録できます。ID は空欄なら自動発行されます（CSV で管理したい場合は `iron_ingot` のような ID を自分で付けられます）。
3. 概要・詳細説明・入手方法・アイコンは任意です。アイコンは最大 128×128 に縮小して保存します。
4. **編集**: カードをダブルクリック、または「編集」。
5. **削除**: 「削除」。ほかのレシピや制作計画から参照されている場合は削除せず、参照箇所の一覧を表示します。先に参照を外してください。

同じ名前でも ID が違えば別アイテムです。

### レシピ

アイテム編集画面の右側で登録します。

* 「レシピを追加」→ レシピ名（任意）、完成数量（1 回の制作でできる個数）、必要素材を入力。
* 「素材を追加…」で検索して選びます。未登録なら選択画面の **「新規作成…」** でその場で作れます。
* 素材 0 種類のレシピも登録できます（採取・購入・報酬など）。
* 同じ素材を 2 行登録することはできません。既存行の数量を編集してください。
* 1 つのアイテムに複数のレシピを登録できます。

「このアイテムを使うレシピ」は自動で表示されます（手で管理する必要はありません）。

---

## 3. 制作計画（キャンバス）

### 計画の作成と切り替え

* 「計画 > 新しい制作計画…」で作成。タブで複数の計画を同時に開けます。
* タブはドラッグで並び替え、中クリックまたは「×」で閉じます。閉じても計画は削除されません。
* 計画の削除は「計画 > この計画を削除…」（確認あり）。
* 再起動すると、前回開いていたタブと選択中のタブが復元されます。

### ノードの配置

| 操作 | 方法 |
| --- | --- |
| 目標アイテムを置く | ツールバー「アイテムを追加…」／左の一覧からキャンバスへドラッグ／一覧の「キャンバスへ」 |
| 素材ツリーを自動生成 | ツールバー「制作計画を追加…」／一覧の「計画を展開」／ノードの「展開」ボタン |
| メモを置く | 「メモを追加」または右クリック →「ここにメモを追加」 |
| 移動 | ノードをドラッグ（Ctrl+クリックで複数選択） |
| 拡大縮小 | マウスホイール |
| 表示位置の移動 | 空白部分をドラッグ |
| 全体表示 | ツールバー「全体表示」 |

* 配置は **製品が左、素材が右** です（鉄の剣 ← 鉄インゴット ← 鉄の原石）。
* 自動配置は既存ノードを動かしません。空き場所が見つからない場合は重ねて置き、通知します。
* 「アイテムを追加」だけでは素材ツリーは展開されません。必要なノードの「展開」を押してください。
* 同じアイテムのノードを複数置けます（統合されません）。

### ノードの表示

ツールバーの **「詳細表示」** で切り替えます（計画全体）。

* シンプル表示: アイコン・名前・必要数量
* 詳細表示: 加えて概要、所持数（編集可）、不足数、制作回数、レシピの選択、素材ごとの切断／再接続

ノードにカーソルを合わせると、名前・概要・入手方法のツールチップが出ます。同じアイテムのノードは強調され、それ以外は暗くなります。

枠の色: **緑** = 所持品だけで直接制作できる、**薄い緑** = 下位素材まで含めれば所持品から制作できる、**青** = 所持数で需要が満たされている。**赤い背景** = 循環レシピの地点。**橙の背景** = 循環の影響で数量が不確定。

### 折りたたみと切断の違い

* **折りたたみ**（ヘッダーの ▾ ボタン）: 下流ノードを一時的に隠すだけ。計算・位置・接続は保持されます。
* **切断**（素材行の「切断」、または接続線の右クリック）: 接続を切り、下流ノードを削除します。アイテムデータは削除されません。切断箇所には赤い破線と **「✂ 素材名（クリックで再接続）」** が表示され、クリックすると下流を再生成します（位置は自動配置、以前の位置は復元しません）。切断された素材は計算に含まれません。
* **接続線だけを削除**（線の右クリック）: 子ノードは独立した目標になります。
* **ノードの削除**（Delete キー／右クリック）: そのノードと下流の子孫ノードをまとめて削除します。親側には切断記録が残り、再接続で生成し直せます。Ctrl+Z で戻せます。

### レシピの変更

詳細表示の「変更…」で、各レシピを使った場合の必要素材を **プレビュー** できます。「採用」を押した時点で計算が更新され、子ノードが再生成されます（共通する素材のノードは位置を保ちます）。

### 手動での接続

ノード右端の **青い丸** を、既存の素材ノードへドラッグすると接続できます。接続先はそのレシピの素材で、まだ親を持たないノードに限ります。

### メモ

テキストの入力、右クリックで背景色の変更、右下の三角をドラッグしてサイズ変更。計算には影響しません。

### キーボード

| 操作 | キー |
| --- | --- |
| 元に戻す／やり直す | Ctrl+Z／Ctrl+Y |
| 選択ノードの削除 | Delete |
| コピー／貼り付け／複製 | Ctrl+C／Ctrl+V／Ctrl+D |
| 手動保存 | Ctrl+S |
| アイテム検索 | Ctrl+F |

ズーム・表示位置・全体表示は Undo の対象外です。

## 4. 数量の計算

右側のパネルに集計が出ます。

* **計画全体（確定値）**: アイテムごとの必要数・所持数（編集可）・余剰・不足。所持数は同じアイテムで共有され、1 回だけ差し引かれます。同じレシピの制作はまとめて回数を求めるため、制作で余った分はほかの需要に充当されます。
* **目標別（参考値）**: 目標ごとに展開した必要数です。所持品をどの目標に使うかは決めないため、不足は参考値です。

計算は選択中のレシピだけを使い、ノードの位置や作成順には依存しません。
1 回で複数個できるレシピは、端数の制作ができないことを考慮して回数を切り上げます。

### 循環レシピ

A ← B ← A のような循環は、検出した地点で展開を止め、その地点の素材を 1 世代だけ表示します。循環の影響を受けるアイテムは「不確定」（数値に `?`）として表示し、無関係な部分の計算は続けます。

---

## 5. 保存・バックアップ・復元

* 編集後 1.5 秒で **自動保存** します。Ctrl+S で即時保存できます。
* 保存は一時ファイルに書いて検証し、既存ファイルを `backups\` に退避してから置き換えます。途中で失敗しても元のファイルは残ります。
* 保存に失敗したときはステータスバーに赤字で表示し、タブに「⚠」が付きます。成功したかのような表示はしません。
* **復元**: 「ファイル > バックアップと復元…」で対象（ゲームデータ／計画）と世代を選び「選択した世代に復元…」。復元前に現在の内容もバックアップされます。壊れたバックアップは復元しません。
* 起動時に読み込めないファイルがあった場合は一覧を表示し、ファイルは **そのまま残します**（初期データで上書きしません）。上記の復元で直前の世代に戻せます。
* バックアップの世代数は `settings.json` の `backupGenerations`（既定 10）で変更できます。

## 6. JSON / CSV

| メニュー | 内容 |
| --- | --- |
| ゲームデータ > JSON に書き出し | アイテム・レシピ・アイコンを含む完全なデータ |
| ゲームデータ > JSON から取り込み | 「新しいゲームデータとして作成」または「現在のゲームデータへ統合」。統合時は ID 競合ごとに 更新（差分表示）／新 ID／除外 を選択 |
| アイテム CSV に書き出し／取り込み | 列 `id,name,summary,description,acquisition`。アイコンは含まれません。空 ID 行は行ごとに 新 ID／取り込まない、競合行は 更新／新 ID／除外 を選択。CSV 内で ID が重複していると取り込みを中止します。アイテム CSV の取り込みではレシピは変更されません |
| レシピ CSV に書き出し | 1 素材 1 行。取り込みは列構成の確認後に提供します |
| 計画 > JSON に書き出し／取り込み | 参照元ゲームデータが一致しない計画は読み込みを拒否します |

取り込みは全件を検証して確認画面を表示し、「適用」で一括反映します。途中で失敗した場合は何も変更しません。

---

## 7. 困ったとき

* **保存に失敗する**: ステータスバーのメッセージと `logs\app-日付.log` を確認してください。ほかのアプリがファイルを開いていないか、ディスク容量を確認します。
* **ファイルが壊れた**: 「バックアップと復元」で直前の世代に戻します。
* **アイテムが削除できない**: 参照している先（レシピの素材、計画のノード・所持数）を先に外します。
* **ノードが重なった**: 空き場所がなかった場合の通知です。手で移動するか、右クリック →「子ノードを整列」。
